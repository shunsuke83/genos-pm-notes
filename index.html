    쉬운 설명: AI 서비스 공장

    GenOS는 공식 문서에서 "End-to-End 노코드 생성형 AI 플랫폼"으로 소개됩니다 확인. PM 관점에서는 사내 문서와 AI 모델로 채팅·보고서 같은 AI 서비스를 만들고, 권한·비용·품질까지 관리하는 플랫폼으로 이해하면 됩니다.

    영역을 누르면 세부 기능과 근거가 나옵니다. 역할을 고르면 그 역할이 주로 쓰는 영역이 강조됩니다.

    노코드의 경계

    "노코드"는 조립 과정이 노코드라는 뜻입니다. 아래 오른쪽 일은 문서상 코드 작업이므로 견적에서 별도 공수로 봐야 합니다.

    화면 설정으로 하는 일

    • 벡터 DB 생성, 문서 업로드와 적재 확인
    • 워크플로우 블록 연결, 채팅 앱 생성과 사용 권한 확인
    • 외부 LLM API 등록, 서비스 라우터 정책 확인
    • 보안등급, 워크스페이스, 크레딧 설정 확인

    코드가 필요한 일

    • 전처리기 맞춤: 파이썬 코드를 facade에 넣는 방식 확인
    • 코드 스페이스·코드 서빙으로 만드는 기능 확인
    • MCP 서버·도구 만들기, 커스텀 노드 함수 확인
    • 파이썬 FastAPI 앱과 GenOS 채팅 연동 확인
    ③

    자사 플랫폼 적용: 두 흐름과 버전 차이

    문서가 검색 가능해지는 흐름(A)과 질문에 답이 돌아오는 흐름(B)을 나눠서 보세요. 장애가 나면 어느 흐름의 어느 단계인지부터 정해야 확인할 화면과 담당자가 정해집니다. 단계를 누르면 상세가 나옵니다.

      각 단계의 기능은 문서에서 확인했습니다. 흐름 B의 2~5단계가 내부에서 정확히 이 순서로 호출되는지는 추정이며, 2회차에서 개발팀 구성도로 확인합니다.

      버전에 따라 달라지는 기능

      • 확인보안등급 문서는 v1.9.0부터, 워크스페이스와 승인(결재) 문서는 v1.9.1부터 목차에 나옵니다. 고객 현장이 이보다 낮은 버전이면 해당 기능이 없을 수 있습니다.
      • 확인 필요태스크플로우 문서는 v1.8.7까지 있고 v1.8.8부터 목차에서 빠졌습니다. 단종인지, 다른 기능에 통합됐는지 알 수 없습니다.
      • 확인v1.6.1-komipo라는 고객사 전용 문서 버전이 있습니다. 표준 제품과 고객 전용 개발이 따로 관리된 사례입니다.
      • 확인워크플로우 이관 문서는 개발망에서 검증한 워크플로우를 결재를 거쳐 운영망에 반영하는 방식을 설명합니다. 망이 분리된 고객 구축을 전제로 한 기능입니다.

      버전 탐색기

      고객 현장 버전과 비교 버전을 고르면, 문서 목차 기준으로 어떤 기능 문서가 있는지 비교합니다. 목차는 버전마다 일정하지 않으므로(예: MCP 문서가 v1.5.4.0에 있다가 v1.6.0~v1.6.2 목차에서 빠짐) 결과는 확인 필요의 출발점으로만 쓰세요.

      기능 문서가 처음 목차에 나온 버전
        ④

        직접 확인 (10분): 문서 기반 채팅 하나를 거꾸로 추적하기

        찾은 값을 적어 두세요. 여기 적은 내용은 저장되고, 채팅에서 요청하면 Claude가 읽습니다.

        예상 결과 채팅 앱 → 워크플로우 → 벡터 DB → 청크가 하나로 이어집니다. 출처 문서를 벡터 DB에서 찾지 못하면, 사용자가 채팅에 직접 첨부한 파일이거나 워크플로우가 여러 벡터 DB를 쓰는 경우일 수 있습니다 추정. 그 경우 학습 기록에 적어 두세요.

        권한이 없다면 DB 문서 적재와 채팅 애플리케이션 사용 문서를 읽고, 1~3단계에서 확인할 화면 항목명을 위 칸에 적어 보세요.

        ⑤

        PM 판단

        고객 설명 문장

        GenOS는 사내 문서를 근거로 답하는 AI 서비스를 만들고, 권한·보안등급·사용량을 한 곳에서 관리하는 플랫폼입니다. 문서를 참고한 답변에는 출처를 함께 보여줍니다.

        확인 전까지 약속하지 않을 것

        • 폐쇄망 설치 가능: 설치 문서가 공개 자료에 없음 확인 필요
        • 동시 사용자 수와 응답시간: 수치 근거 없음 확인 필요
        • 정확도 수치: 평가 데이터와 판정 기준을 먼저 합의해야 함
        • SSO 연동: 공개 문서 목차에 없음 확인 필요
        구분판단에 주는 영향누가 정하나
        범위제안서에 대상 버전을 반드시 적습니다. 같은 요구도 버전에 따라 "기본 제공"이 되거나 "업그레이드 필요"가 됩니다.버전 명시는 내가 결정, 현장 버전의 기능은 개발팀 확인
        일정개발망→운영망 이관에는 결재와 양쪽에서 접근 가능한 Git 저장소 준비가 필요합니다. 이관 기간을 일정에 넣어야 합니다.이관 소요 기간은 개발팀 확인
        비용노코드여도 전처리기 맞춤, MCP 도구, 코드 서빙은 개발 공수입니다. 외부 API를 쓰면 토큰 요금(원/100만 토큰)이 생깁니다.가정 명시는 내가 결정, 공수는 개발팀 확인
        검수출처 표시는 화면에서 확인할 수 있어 검수 항목으로 쓰기 좋습니다. 출처가 정확하다고 판정하는 기준은 고객과 합의해야 합니다.기준 제안은 내가 결정, 수치는 고객 합의
        리스크문서 목차가 버전마다 일정하지 않습니다. 문서만 보고 기능 유무를 단정하면 안 됩니다.실제 탑재 여부는 개발팀 확인

        개발팀에 확인할 질문

        1. 담당 고객 현장 버전에 보안등급과 워크스페이스가 실제로 탑재돼 있나요?부서별 권한 요구를 기본 기능으로 대응할 수 있는지가 달라집니다.
        2. 태스크플로우는 단종됐나요, 다른 기능으로 통합됐나요?구버전 고객의 유지보수와 업그레이드 범위에 영향을 줍니다.
        3. 외부 LLM API를 쓰면 어떤 데이터가 플랫폼 밖으로 나가나요?공공·금융 고객의 보안 심사에서 반드시 묻는 항목입니다.
